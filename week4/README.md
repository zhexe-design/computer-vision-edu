# Week 4 — Point Cloud Registration (ICP)

Week 4 extends the 3D point-cloud workflow from Week 3 (preprocessing) to **rigid registration**: aligning a source point cloud with a target. The project combines coarse global alignment, local ICP refinement, and quantitative evaluation. It also includes a from-scratch point-to-point ICP implementation and experiments on registration accuracy.

**Stack:** Python, Open3D, NumPy, SciPy, Matplotlib  
**Core pipeline:** preprocessing → FPFH + RANSAC → ICP refinement → fitness / inlier RMSE evaluation

---

## Prerequisites: Week 3

Week 3 introduced voxel downsampling, statistical and radius outlier removal, normal estimation, and ROI cropping. These operations prepare point clouds for registration by reducing noise and computational cost.

## Registration pipeline

1. **Load** source and target point clouds (PLY/PCD; meshes can be sampled into point clouds).
2. **Preprocess** the clouds: remove invalid points and outliers, then downsample with voxels.
3. **Estimate normals** for feature computation and point-to-plane ICP.
4. **Find a coarse alignment** with FPFH features and RANSAC.
5. **Refine the pose** with point-to-point ICP, point-to-plane ICP, or the custom NumPy/SciPy implementation.
6. **Evaluate and export** the alignment, merged cloud, visualizations, and metrics.

```text
Source ──► preprocess ──► FPFH + RANSAC ──► ICP refinement ──► aligned cloud
Target ──► preprocess ────────┘                         └──► metrics + outputs
```

ICP is a local optimization method. If the initial pose is too far from the correct alignment, ICP may converge to a poor local solution; global registration provides a coarse starting pose.

## Results

### Scan registration

The Day 4 scan-pair experiments compared Open3D registration with the custom ICP implementation. The values below are the recorded results for the two tested pairs.

| Scan pair | Method | Fitness | Inlier RMSE |
| --- | --- | ---: | ---: |
| scan1 → scan2 | Open3D | 0.6658 | 0.022309 |
| scan1 → scan2 | Custom ICP | 0.6665 | 0.022146 |
| scan2 → scan3 | Open3D | 0.8020 | 0.022053 |
| scan2 → scan3 | Custom ICP | 0.8123 | 0.022970 |

Fitness is the fraction of source points that have a correspondence within the configured distance threshold. Inlier RMSE measures the error among accepted correspondences. Both metrics depend on the threshold and the amount of overlap, so they should be interpreted together.

### Custom ICP

The custom point-to-point ICP implementation demonstrates the main registration loop:

- nearest-neighbour correspondence search with a KD-tree;
- rigid transformation estimation using SVD;
- reflection correction;
- iterative transformation updates and convergence checks.

A synthetic known-transform test is useful for checking implementation correctness, but near-zero synthetic error should not be presented as evidence of equivalent performance on partial or noisy real scans.

## How to run

Run commands from the repository root. Install the registration dependencies:

```bash
pip install open3d numpy scipy matplotlib imageio
```

### Day 3 — global registration experiments

```powershell
python "week4/day 3/day3_global_registration.py"
```

### Day 4 — register two scans

```powershell
python "week4/day 4/day4_phone_scans.py" `
  --source "week4/day 4/data/scan1.ply" `
  --target "week4/day 4/data/scan2.ply"
```

### Day 5 — registration pipeline

```powershell
python "week4/day 5/register.py" `
  --source "path/to/scan1.ply" `
  --target "path/to/scan2.ply" `
  --method p2l `
  --make-gif
```

Supported methods: `p2p`, `p2l`, and `my_icp`. Use `--no-global` to skip coarse global registration. Check each script's `--help` output for all available options.

## Design choices

| Choice | Reason |
| --- | --- |
| FPFH + RANSAC before ICP | Provides a coarse pose when the initial alignment is poor. |
| Point-to-plane ICP | Can converge efficiently on surfaces when normals are reliable. |
| Voxel downsampling | Reduces computational cost and helps control the scale of preprocessing. |
| Custom ICP | Makes correspondence search and rigid-transform estimation explicit rather than relying only on a library call. |
| Fitness + Inlier RMSE | Gives a more useful view of alignment quality than either metric alone. |

---

## Limitations

- The workflow performs rigid registration; it does not model non-rigid or deformable motion.
- Registration quality depends on overlap, noise, point density, scale, and the correspondence distance threshold.
- ICP is sensitive to initialization and can converge to a local minimum.
- The custom implementation is point-to-point; point-to-plane refinement is provided by Open3D.
- Results from one scan pair should not be generalized to other datasets without retuning and evaluation.
- Synthetic tests validate controlled cases but do not replace evaluation on partial, noisy real-world scans.
- Large source datasets and model checkpoints should be downloaded or generated locally rather than committed to Git.
